# Agents

How each coding agent registers a local MCP server, where it reads skills, and whether it has a hook that runs before a tool call. `repomagpie setup` and `repomagpie doctor` rely on these facts ([decision 0034](decisions/0034-the-mcp-server.md), [decision 0035](decisions/0035-setup-and-doctor.md)).

Every fact below was checked on **2026-10-14** against the source linked next to it, unless a row says otherwise. Agent config formats change monthly: check the source again before changing `setup` for an agent, and update the date. "Not documented" means the agent's own docs don't say; it doesn't mean the feature is missing.

`~` is the home folder: `%USERPROFILE%` on Windows.

## Summary

`setup` writes the MCP entry, the skill and (Claude Code only) the hook for the **first set**. For the others it prints the snippet and the path.

| Agent | MCP at user scope | Skills (user scope) | Hook before a tool call | `setup` |
|---|---|---|---|---|
| Claude Code | `claude mcp add --scope user` → `~/.claude.json` | `~/.claude/skills/` | `PreToolUse`: allow, deny, ask; context for the agent | first set |
| Codex CLI | `codex mcp add` → `~/.codex/config.toml` (TOML) | `~/.agents/skills/` | `PreToolUse`: deny, allow; context; `ask` not supported yet | first set |
| Cursor | `~/.cursor/mcp.json` (JSON edit) | `~/.agents/skills/`, `~/.cursor/skills/` (also reads `~/.claude/skills/`, `~/.codex/skills/`) | `beforeShellExecution`: allow, deny, ask (`ask` not reliable) | first set |
| Gemini CLI | `gemini mcp add --scope user` → `~/.gemini/settings.json` | `~/.gemini/skills/` or `~/.agents/skills/` | `BeforeTool`: allow, deny; no `ask`; a message for the user | first set |
| VS Code (GitHub Copilot) | `code --add-mcp` → the user profile's `mcp.json` | `~/.copilot/skills/`, `~/.claude/skills/`, `~/.agents/skills/` | `PreToolUse` (Preview): ask shown in the docs | first set |
| Copilot CLI | `copilot mcp add` → `~/.copilot/mcp-config.json` | `~/.copilot/skills/`, `~/.agents/skills/` | `preToolUse`: allow, deny, ask; no context on allow; a non-zero exit denies | snippet |
| Windsurf (Devin Desktop) | `~/.config/devin/mcp_config.json`; Windows `%APPDATA%\devin\mcp_config.json` | not documented (`~/.codeium/windsurf/skills/` per `npx skills`) | `pre_run_command`: proceed or block (exit 2) | snippet |
| Cline | `cline mcp add` → `~/.cline/data/settings/cline_mcp_settings.json` (CLI) | `~/.agents/skills/` per `npx skills` | SDK plugins: `beforeTool` can skip, require approval, add context | snippet |
| Zed | `context_servers` in Zed's `settings.json` | `~/.agents/skills/` | not documented; tool permission prompts instead | snippet |
| OpenCode | `mcp` in `~/.config/opencode/opencode.json` (JSONC allowed) | `~/.config/opencode/skills/` | plugins: `tool.execute.before` can block by throwing | snippet |
| Goose | `extensions` in `~/.config/goose/config.yaml`; Windows `%APPDATA%\Block\goose\config\config.yaml` | not documented (`~/.config/goose/skills/` per `npx skills`) | not documented | snippet |
| Claude Desktop | `mcpServers` in `claude_desktop_config.json` (macOS `~/Library/Application Support/Claude/`, Windows `%APPDATA%\Claude\`) | not documented | not documented | snippet |
| Antigravity CLI | `~/.gemini/config/mcp_config.json` (JSON edit) | `~/.gemini/antigravity-cli/skills/` | `PreToolUse`: allow, deny, ask, `force_ask`; `reason` only | not yet (by hand) |

## The first set

### Claude Code
- **MCP:** `claude mcp add [options] <name> -- <command> [args...]`, with `--scope user` for "available to you across all projects". "Everything after `--` is passed to the server untouched." User-scope servers are stored in `~/.claude.json`, at its top level; the docs don't show the exact shape. Remove with `claude mcp remove`. `claude mcp add-json <name> '<json>' --scope user` takes the entry as JSON. Source: [Claude Code MCP](https://code.claude.com/docs/en/mcp).
- **Why the CLI, not a JSON edit:** `~/.claude.json` also holds Claude Code's own state, and Claude Code rewrites it while it runs.
- **Limits that affect us:** server instructions, and the description of a tool that loads upfront, are cut at 4,096 characters. Claude Code sets `CLAUDE_PROJECT_DIR` in the server's environment. On connections that use the 2026-07-28 revision it declares elicitation; we don't use it ([decision 0034](decisions/0034-the-mcp-server.md)). Same source.
- **Windows:** community reports say an npx-based server needs `cmd /c npx …` on native Windows, and that `claude mcp add` once rewrote the `/c` argument into `C:/` ([report](https://claudeissues.com/issue/20061-windows-claude-mcp-add-mangles-c-flag-breaks-npx-based-mcp-servers); not in Anthropic's docs). The absolute `node` entry ([decision 0035](decisions/0035-setup-and-doctor.md)) needs neither.
- **Skills:** personal `~/.claude/skills/<name>/SKILL.md`; project `.claude/skills/`, in the start folder and every parent up to the repository root. The docs don't mention `~/.agents/skills/`. Source: [Claude Code skills](https://code.claude.com/docs/en/skills).
- **Hook:** `PreToolUse` in `~/.claude/settings.json` or the project's `.claude/settings.json`; `permissionDecision` `allow`, `deny` or `ask`; `additionalContext` reaches the agent. Checked against the [hooks reference](https://code.claude.com/docs/en/hooks) on 2026-10-04 ([spec](spec.md), section 6).
- **How a hook command runs** (same source, checked 2026-10-14): in **shell form** (no `args`), "the `command` string is passed to a shell: `sh -c` on macOS and Linux, Git Bash on Windows, or PowerShell when Git Bash isn't installed"; a hook's `shell` field (`"bash"` or `"powershell"`) chooses. In **exec form** (with `args`), Claude Code spawns the executable directly, with no shell; on Windows `command` must then be a real executable, not a `.cmd` shim. Measured on a Windows dev machine (2026-10-14, the packed package installed with npm, median of 20): `repomagpie hook claude-code` through Git Bash and npm's shell shim 268 ms; the absolute `node` and entry file through Git Bash 114 ms; `repomagpie.cmd` through `cmd` 99 ms; `node` started directly, as exec form would, 74 ms. Exec form as `setup` writes it, with `--disallow-code-generation-from-strings`: 86 ms (re-measured the same day, shell form 281 ms). Exec form fields, from the same source: `"command"` is "the executable to spawn directly", "resolved as an executable on `PATH`", an absolute path with spaces (`C:\Program Files\nodejs\node.exe`) being "a single valid executable"; each `args` element is passed "exactly as written".

### Codex CLI
- **MCP:** `codex mcp add <server-name> --env VAR1=VALUE1 -- <stdio server-command>`, stored in `~/.codex/config.toml` as `[mcp_servers.<name>]` with `command`, `args`, `env`, `env_vars` ("allow and forward"), `cwd`, `startup_timeout_sec` (default 10), `tool_timeout_sec` (default 60), `enabled`, `required`, `enabled_tools`, `disabled_tools`, and `default_tools_approval_mode` (`auto`, `prompt`, `writes` or `approve`). A project `.codex/config.toml` works for trusted projects only. Remove with `codex mcp remove`. Source: [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) (formerly developers.openai.com/codex/mcp, which redirects there).
- **Never set** `default_tools_approval_mode` or a per-tool `approval_mode`: approval is the user's choice ([decision 0035](decisions/0035-setup-and-doctor.md)).
- **Environment:** the docs don't say which variables reach a server. Codex's source passes a default list (on Unix the user, home and `PATH` variables; on Windows also `COMSPEC`, `SYSTEMROOT`, `APPDATA` and others) plus `env_vars`, so API keys aren't forwarded unless configured. Source: Codex's `codex-rs/rmcp-client/src/utils.rs`, read through a [mirror](https://forge.lthn.ai/core/core-agent-ide/src/commit/01ca2b5df666ca2594ce26b2867cc1a4337cc21e/codex-rs/rmcp-client/src/utils.rs) and [PR 4811](https://github.com/openai/codex/pull/4811/files); not in the docs.
- **Skills:** `$CWD/.agents/skills`, each parent up to `$REPO_ROOT/.agents/skills`, `$HOME/.agents/skills`, `/etc/codex/skills`, and the bundled ones. Two skills with the same name both appear. Source: [Codex skills](https://learn.chatgpt.com/docs/build-skills.md). Older guides name `~/.codex/skills/`; the docs no longer do.
- **Hook** (checked 2026-10-15): `PreToolUse` in `~/.codex/hooks.json` or `[hooks]` in `config.toml` (project ones only when the project's `.codex/` is trusted); on by default (`[features] hooks = false` turns them off; `codex_hooks` is a deprecated alias). An entry is `{ "matcher": "Bash", "hooks": [{ "type": "command", "command", "timeout", "statusMessage" }] }`; `commandWindows` (TOML `command_windows`) replaces `command` on Windows. Input on stdin: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model`, `turn_id`, `tool_name` (`Bash` for shell commands), `tool_use_id`, `tool_input` (`command` for Bash), `permission_mode`; "Commands run with the session `cwd` as their working directory." Output: `permissionDecision: "deny"` with `permissionDecisionReason` blocks; `"allow"` with `updatedInput` rewrites the call; `"ask"` is "parsed but not supported yet" (the run is marked failed and the call continues); `additionalContext` "adds model-visible context without blocking"; `systemMessage` "surfaces a warning". "Exit `0` with no output is treated as success"; exit 2 blocks with stderr as the reason; "Plain text on `stdout` is ignored." `timeout` is in seconds, default 600. Source: [Codex hooks](https://learn.chatgpt.com/docs/hooks).
- **Trust** (checked 2026-10-15): "Codex records trust against the hook's current hash, so new or changed hooks are marked for review and skipped until trusted." The user trusts a hook in `/hooks`; `--dangerously-bypass-hook-trust` skips trust for one run (`setup` never uses or suggests it). Same source. Where it is kept, read in Codex's source (`codex-rs/hooks/src/engine/discovery.rs`, main, 2026-10-15): in `config.toml`, `[hooks.state."<hook file>:pre_tool_use:<group index>:<handler index>"]` with `trusted_hash` (a string starting `sha256:`) and `enabled`; the hash covers the event, the matcher and the normalised handler (command, timeout, status message), not the script it runs ([openai/codex#49398](https://github.com/openai/codex/issues/49398)). So any change to our entry's command or timeout needs trusting again.
- **How the hook command runs**, read in Codex's source (`codex-rs/hooks/src/engine/command_runner.rs`, main, 2026-10-15): through the session's shell when one is configured; otherwise `%COMSPEC% /C "<command>"` (`cmd.exe` when `COMSPEC` is unset) on Windows and `$SHELL -lc` (`/bin/sh`) elsewhere. A third-party fix says Codex runs hooks through PowerShell on Windows ([NVIDIA/NeMo-Relay#1244](https://github.com/NVIDIA/NeMo-Relay/pull/1244), Codex 0.160.1); the pre-check records which one runs.
- **Windows:** before CLI 0.159.0, `PreToolUse` didn't fire for shell commands on Windows ([openai/codex#24453](https://github.com/openai/codex/issues/24453), closed 2026-10-12 as "reported resolved in CLI 0.159.0").

### Cursor
- **MCP:** "Create `~/.cursor/mcp.json` in your home directory for tools available everywhere"; project `.cursor/mcp.json`. Shape: `mcpServers` → `{ "type": "stdio", "command", "args", "env", "envFile" }`. `command` "must be available on your system path or contain its full path." `command`, `args` and `env` expand `${env:NAME}`, `${userHome}`, `${workspaceFolder}` and `${/}`. No command-line way to add a server is documented; extensions can call `vscode.cursor.mcp.registerServer()`. Source: [Cursor MCP](https://cursor.com/docs/context/mcp).
- **JSON with comments:** not documented. `setup` edits the file only when it is plain JSON ([decision 0035](decisions/0035-setup-and-doctor.md)).
- **Skills:** project `.agents/skills/`, `.cursor/skills/`; user `~/.agents/skills/`, `~/.cursor/skills/`; "for compatibility" also `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/` and `~/.codex/skills/`. Source: [Cursor skills](https://cursor.com/docs/context/skills).
- **Hook** (checked 2026-10-15): `~/.cursor/hooks.json` or `<project>/.cursor/hooks.json`: `{ "version": 1, "hooks": { "beforeShellExecution": [{ "command", "timeout", "matcher" }] } }`; `timeout` in seconds ("platform default" when left out, no number given); `matcher` a regex. User hooks run from `~/.cursor/`, project hooks from the project root; `command` is "a shell string, an absolute path, or a relative path" (the shell isn't named). Input: `command`, `cwd`, `sandbox`, plus `conversation_id`, `generation_id`, `model`, `hook_event_name`, `cursor_version`, `workspace_roots`, `user_email`, `transcript_path`. Output: `permission` (`allow`, `deny`, `ask`), `user_message` ("shown in the client"), `agent_message` ("sent to the agent"). Exit 0 uses the JSON; exit 2 equals `deny`; other exit codes: "Hook failed, action proceeds (fail-open by default)"; "no output" counts as a failure; **invalid JSON, or output that doesn't match the schema, blocks**; `failClosed: true` blocks on every failure. The docs don't say what `{}` or `allow` does to the user's own approval. Source: [Cursor hooks](https://cursor.com/docs/agent/hooks).
- **`ask` isn't reliable** (forum, checked 2026-10-15): on 2.4.21 a `beforeShellExecution` `ask` ran the command without a prompt; Cursor staff called it "a known issue" and suggested "use `deny` instead of `ask` for critical operations" (2026-01-27; no fix posted) ([ask broken](https://forum.cursor.com/t/hooks-ask-permission-broken-in-2-4-21/150020)). A later thread title reports `ask` "ignored in Auto-review mode (honoured in Allowlist and Run Everything), 3.21.16" (2026-10-06). On `preToolUse`, "right now only `deny` is respected" (a reply, 2026-05-23), and a user reports that "`{}` currently defaults to `allow` in cursor" (2026-07-09), not confirmed by Cursor ([authoritative verdicts](https://forum.cursor.com/t/support-authoritative-allow-deny-and-ask-verdicts-from-hooks/161342)). Whether an empty answer skips the user's approval is what the pre-check tests ([decision 0036](decisions/0036-hooks-in-other-agents.md)).

### Gemini CLI
- **MCP:** `gemini mcp add [options] <name> <commandOrUrl> [args...]`; `-s, --scope` is `user` or `project` (default `project`); user scope writes `~/.gemini/settings.json`. Entry: `mcpServers` → `{ "command", "args", "env", "cwd", "timeout", "trust", "includeTools", "excludeTools" }`. `trust: true` "bypasses all tool call confirmations for this server"; `--trust` sets it. Stdio servers show as connected only in a trusted folder. Source: [Gemini CLI MCP](https://geminicli.com/docs/tools/mcp-server/).
- **Never set `trust`** ([decision 0035](decisions/0035-setup-and-doctor.md)).
- **Environment:** Gemini CLI "redacts sensitive environment variables from the base environment (inherited from the host process)": names matching `*TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*KEY*`, `*AUTH*`, `*CREDENTIAL*`. So `GITHUB_TOKEN` doesn't reach our server there, which is fine: the MCP tools never call GitHub ([decision 0034](decisions/0034-the-mcp-server.md)). Same source.
- **Skills:** user `~/.gemini/skills/` or the `~/.agents/skills/` alias; workspace `.gemini/skills/` or `.agents/skills/`. Within a tier, `.agents/skills/` wins. `gemini skills install <git-url or path> --scope user`. Source: [Gemini CLI skills](https://geminicli.com/docs/cli/skills/).
- **Hook** (checked 2026-10-15): `BeforeTool` in `settings.json` → `hooks`: `[{ "matcher": "run_shell_command", "hooks": [{ "type": "command", "command", "name", "timeout" }] }]`; `timeout` in milliseconds, default 60000. Input: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `timestamp`, `tool_name`, `tool_input`, `mcp_context`, `original_request_name`. Output: `decision` `allow` or `deny` (`block` is an alias), `reason` (sent to the agent as a tool error on deny), `systemMessage` ("Displayed immediately to the user in the terminal"), `continue`, `hookSpecificOutput.tool_input` (rewrites the call). No `ask`; no `additionalContext` on `BeforeTool`. The docs: exit 0 parses stdout as JSON, exit 2 blocks with stderr as the reason, "Other: Warning … the CLI continues". Source: [Gemini CLI hooks reference](https://geminicli.com/docs/hooks/reference/).
- **In Gemini CLI's source** (`packages/core/src/hooks/hookRunner.ts`, main, 2026-10-15), which differs from the docs: exit 1 is a warning, and "All other non-zero exit codes (including 2) are blocking". Plain text on stdout becomes a `systemMessage` on success. The hook gets `GEMINI_PROJECT_DIR`, `GEMINI_CWD`, `GEMINI_SESSION_ID` and `CLAUDE_PROJECT_DIR` (all the call's `cwd`). The command runs through `getShellConfiguration()` (`packages/core/src/utils/shell-utils.ts`): on Windows always PowerShell (`ComSpec` when it names `powershell.exe` or `pwsh.exe`, else `pwsh.exe` on `PATH`, else `powershell.exe`, with `-NoProfile -NonInteractive -Command`), never `cmd`; elsewhere `bash -c`. So a quoted absolute path needs PowerShell's `&` there. The shell tool's input (`packages/core/src/tools/shell.ts`): `command`, `description`, `dir_path`, `is_background`, `delay_ms`.
- **Turning hooks off:** `hooksConfig.enabled` ("When disabled, no hooks will be executed", default `true`) and `hooksConfig.disabled` (hook names that won't run). `/hooks enable-all`, `disable-all`, `enable <name>`, `disable <name>`. Project hooks are fingerprinted: a changed name or command is "treated as a new, untrusted hook and you will be warned before it executes"; nothing is said of user hooks. Sources: [configuration reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md), [Gemini CLI hooks](https://geminicli.com/docs/hooks/).
- **Note:** the same page says Gemini CLI "was replaced by Antigravity CLI on June 18th, 2026, for unpaid tier and Google One users". Antigravity CLI keeps its own files ([below](#antigravity-cli)), also under `~/.gemini`, so `setup` and `doctor` count Gemini CLI as installed only by its `settings.json` or the `gemini` command, not by the folder.

### VS Code (GitHub Copilot)
- **MCP:** the user profile's `mcp.json`, opened with "MCP: Open User Configuration"; servers there "are available across all your workspaces", and each profile has its own. Workspace: `.vscode/mcp.json`. Shape: `servers` (not `mcpServers`) → `{ "type": "stdio", "command", "args", "cwd", "env", "envFile" }`. From a terminal: `code --add-mcp "{\"name\":\"my-server\",\"command\":\"uvx\",\"args\":[\"mcp-server-fetch\"]}"` adds a server to the user profile. Sources: [VS Code MCP servers](https://code.visualstudio.com/docs/copilot/customization/mcp-servers), [MCP configuration reference](https://code.visualstudio.com/docs/copilot/reference/mcp-configuration).
- **The user `mcp.json`'s path** isn't in the docs. Checked on a real install (VS Code on Windows, 2026-10-14): `code --user-data-dir <scratch> --add-mcp '{"name":…,"command":…,"args":[…]}'` printed `Added MCP servers: <name>` and wrote `<user data dir>/User/mcp.json`, indented with tabs, with `servers` and an empty `inputs`, and no `type`. The default user data dir is `%APPDATA%\Code` on Windows, `~/Library/Application Support/Code` on macOS and `~/.config/Code` on Linux ([VS Code CLI docs](https://code.visualstudio.com/docs/configure/command-line)), so the file is `…/Code/User/mcp.json`.
- **Not documented:** whether comments are allowed; a command-line remove. `setup` adds through `code --add-mcp`; it changes or removes an entry by editing the file when it is plain JSON, and otherwise points the user to it.
- **Trust:** "VS Code shows a dialog when a server first starts or its configuration changes" for servers outside a trusted workspace's files. Same source.
- **Other files:** the portable `~/.copilot/mcp-config.json` (`mcpServers`) is read by the Agent Host, and by discovery when `chat.mcp.discovery.enabled` is on (off by default). Same source.
- **Skills:** personal `~/.copilot/skills/`, `~/.claude/skills/`, `~/.agents/skills/`; project `.github/skills/`, `.claude/skills/`, `.agents/skills/`. Source: [VS Code agent skills](https://code.visualstudio.com/docs/copilot/customization/agent-skills).
- **Hook** (checked 2026-10-15): "The VS Code hooks experience is in Preview." User hooks in `~/.copilot/hooks/*.json`, **the folder Copilot CLI reads too**; workspace `.github/hooks/*.json`; Claude Code's `settings.json` files only with `chat.useClaudeHooks` (off by default); `chat.useHooks` is on by default. Its own format uses PascalCase events (`PreToolUse`) with `command` and `windows`, `linux`, `osx` overrides; a file "with a numeric `version` property and lower camel case events" (Copilot CLI's) is mapped to it. Source: [VS Code hooks](https://code.visualstudio.com/docs/copilot/customization/hooks). Input: `timestamp`, `cwd`, `session_id`, `hook_event_name`, `transcript_path`, `tool_name`, `tool_input`, `tool_use_id`; the terminal tool's name isn't documented ("Tool names and arguments differ between harnesses"). Output: `permissionDecision` `allow`, `deny` or `ask` ("the most restrictive one applies"), `permissionDecisionReason` ("shown to the user"), `additionalContext` ("for the model"). Exit 0 processes stdout; exit 2 blocks with stderr for the model; any other "Show[s] a non-blocking warning". `timeout` in seconds, default 30. The Windows shell isn't named. Source: [Local hooks reference](https://code.visualstudio.com/docs/agents/reference/hooks-reference). Whether VS Code sends its own input to a Copilot CLI-format file is what the pre-check records.

## The others (snippet only)

### Copilot CLI
- **MCP:** `copilot mcp add SERVER-NAME -- COMMAND [ARGS...]`, with `--env KEY=VALUE`; stored in `~/.copilot/mcp-config.json` (`COPILOT_HOME` moves it) under `mcpServers` → `{ "type": "local", "command", "args", "env", "tools": ["*"] }`. "The `PATH` variable is automatically inherited from your environment. All other environment variables must be configured here." Sources: [add MCP servers](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers), [use Copilot CLI](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-copilot-cli).
- **Skills:** personal `~/.copilot/skills/` or `~/.agents/skills/`; project `.github/skills/`, `.claude/skills/` or `.agents/skills/`. Source: [add skills](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills).
- **Hook** (checked 2026-10-15): user `*.json` files in `~/.copilot/hooks/` (`$COPILOT_HOME/hooks/` when set; any file name), repository `.github/hooks/*.json`, also a repository's `.claude/settings.json`. VS Code reads the same user folder (above). A file: `{ "version": 1, "hooks": { "preToolUse": [{ "type": "command", "bash", "powershell", "command" (the cross-platform fallback), "cwd", "env", "timeoutSec" }] } }`; `timeoutSec` (alias `timeout`) in seconds, default 30. Input: `sessionId`, `timestamp` (Unix milliseconds), `cwd`, `toolName` (the shell tool is `bash` on macOS and Linux, `powershell` on Windows), `toolArgs` (typed `unknown`; its shape for the shell tool isn't documented). Output: `permissionDecision` `allow`, `deny` or `ask` (the cloud agent treats `ask` as `deny`), `permissionDecisionReason` (required on `deny`), `modifiedArgs`; "Empty output uses default behavior"; no `additionalContext` on `preToolUse`. Exit 2 denies the call, and so does any other non-zero exit or a crash ("fail-closed"); timeouts fail open. A `"disableAllHooks": true` in a hook file skips that file's hooks. A "VS Code compatible format" (PascalCase `PreToolUse`, snake_case fields, Claude tool names such as `Bash`) exists for hook payloads. Which PowerShell runs the `powershell` command isn't said. Source: [Copilot hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference).

### Windsurf (Devin Desktop)
- The docs now call the product Devin Desktop; the old Windsurf URLs redirect.
- **MCP:** `mcpServers` → `{ "command", "args", "env" }` in `~/.config/devin/mcp_config.json` (or `$XDG_CONFIG_HOME/devin/`) on macOS and Linux, `%APPDATA%\devin\mcp_config.json` on Windows. `${env:VAR}` and `${file:/path}` expand. No command-line way to add one. The older `~/.codeium/windsurf/mcp_config.json` isn't on the page any more. Source: [Cascade MCP](https://docs.devin.ai/desktop/cascade/mcp).
- **Skills:** not documented. `npx skills` installs into `~/.codeium/windsurf/skills/` ([skills CLI](https://github.com/vercel-labs/skills)).
- **Hook:** user `~/.codeium/windsurf/hooks.json`, workspace `.devin/hooks.json`. `pre_run_command` gets `tool_info.command_line` and `cwd`; exit 0 proceeds, exit 2 blocks and "the Cascade agent will see the error message from stderr". No ask, and no documented way to pass context on an allowed command. Source: [Cascade hooks](https://docs.devin.ai/desktop/cascade/hooks).

### Cline
- **MCP:** the CLI keeps servers in `~/.cline/data/settings/cline_mcp_settings.json` (`CLINE_MCP_SETTINGS_PATH` moves it); `cline mcp add <name> --yes -- <command> [args]` adds one. In the IDE extensions, the file opens from the MCP Servers panel; its path isn't documented. Shape: `mcpServers` → `{ "command", "args", "env", "disabled", "autoApprove": [] }`. - **Hook:** SDK plugins have `beforeTool`, which can return `skip` with a reason ("goes back to the model"), replace the input, return `policy: { autoApprove: false }` to require approval, or `appendContext`. File-based hooks aren't documented on that page. Source: [Cline SDK plugins](https://docs.cline.bot/sdk/plugins).

### Antigravity CLI
- Google's agent CLI (`agy`), which replaced Gemini CLI for unpaid tiers on 2026-06-18 (Gemini CLI, above). Read from its docs on 2026-10-14, not yet tried on a machine. `repomagpie setup` and `repomagpie doctor` don't know it yet ([roadmap](roadmap.md)).
- **MCP:** `mcpServers` → `{ "command", "args", "env" }` in `~/.gemini/config/mcp_config.json` (global, shared with the Antigravity IDE) or `.agents/mcp_config.json` (workspace). No documented command to add one; `/mcp` shows the servers and reloads the file. Not `~/.gemini/settings.json`, which is Gemini CLI's. Source: [Antigravity MCP](https://antigravity.google/docs/mcp/). Each product keeps a cache of installed servers (`~/.gemini/antigravity-cli/mcp/` for the CLI), so a removed entry can stay listed until that folder is cleared: [Where does Antigravity look for MCP servers?](https://atamel.dev/posts/2026/07-10_where_agy_mcp_servers/) (a blog post by a Google developer advocate, 2026-07-10).
- **Skills:** the CLI reads `~/.gemini/antigravity-cli/skills/<name>/`; the IDE reads `~/.gemini/config/skills/<name>/` (and the older `~/.gemini/antigravity/skills/`); both read a workspace's `.agents/skills/`. `~/.agents/skills/` isn't listed. Source: [Antigravity skills](https://antigravity.google/docs/skills).
- **Hook** (checked 2026-10-15): global `~/.gemini/config/hooks.json` (shared with the Antigravity IDE) or inside `~/.gemini/antigravity-cli/settings.json` (CLI only); workspace `.agents/hooks.json`. The top-level keys are hook names: `{ "<hook name>": { "enabled": true, "PreToolUse": [{ "matcher": "run_command", "hooks": [{ "type": "command", "command", "timeout" }] }] } }`; `timeout` in seconds, default 30; `"enabled": false` turns one hook off; no switch for all hooks is documented, and no trust step. Input for `run_command`: `toolCall.name`, `toolCall.args.CommandLine`, `toolCall.args.Cwd`, `toolCall.args.WaitMsBeforeAsync`, `stepIdx`, `conversationId`, `workspacePaths`, `transcriptPath`, `artifactDirectoryPath`, `modelName`. Output: `decision` (required) — `allow` "Allows the tool call to proceed, delegating to the next hook or default policy"; `ask` "Prompts you for approval, but respects "Always Allow" settings"; `force_ask` "Always prompts you for approval, ignoring cached permissions"; `deny` "Hard blocks execution immediately"; `auto_approve` "Automatically approves the tool call when the default policy would otherwise prompt"; `deny_unless_prior_grant` — and `reason`, "The explanation shown to the agent or to you for the decision". The shell that runs `command`, exit codes and errors aren't documented, and Antigravity CLI isn't open source: the pre-check records them. Source: [Antigravity hooks](https://antigravity.google/docs/hooks).
- **Install** (checked 2026-10-15): `irm https://antigravity.google/cli/install.ps1 | iex` in PowerShell, `curl -fsSL https://antigravity.google/cli/install.sh | bash` elsewhere; sign in with a Google account at first start. Source: [getting started](https://antigravity.google/docs/getting-started?tab=cli).

## Who gets the shell's `PATH`

An MCP server inherits the environment of the agent that starts it. What that environment holds depends on how the agent was opened, and only one agent documents it.

| Agent | Started from | Its servers' `PATH` |
|---|---|---|
| Claude Code, Codex CLI, Gemini CLI, Copilot CLI, Cline CLI, OpenCode | a terminal | the shell's. Copilot CLI documents it ("The `PATH` variable is automatically inherited"). Codex passes `PATH` in its default list (source code, above). Gemini CLI passes the inherited environment minus secret-looking names. The others don't say. |
| Cursor, VS Code, Windsurf, Zed, Claude Desktop, Goose's desktop app | the Dock, the Start menu, a launcher | the launch environment, not the shell profile's. Not documented by any of them. On macOS, an app opened from the Dock gets launchd's short `PATH` without Homebrew's or nvm's folders; Claude Desktop's `spawn npx ENOENT` is the known result ([report](https://github.com/tomaspavlin/rohlik-mcp/issues/6)). VS Code resolves the login shell's environment at start on macOS and Linux ([a Claude Code issue that compares the two](https://claudeissues.com/issue/44649-claude-code-desktop-mac-does-not-inherit-user-shell-path-when-launched-from-dock); not in VS Code's docs). On Windows, apps get the user's and the system's `PATH` from the registry, which usually includes npm's global folder, but `repomagpie` there is a `.cmd` shim. |

**Windows `.cmd` shims:** "`.bat` and `.cmd` files are not executable on their own without a terminal", so a process started without a shell can't run them ([Node.js child_process](https://nodejs.org/api/child_process.html)). npm installs `repomagpie` as `repomagpie.cmd` on Windows.

That is why `setup` writes the absolute `node` and the absolute entry file, never `repomagpie` ([decision 0035](decisions/0035-setup-and-doctor.md), "How agents launch RepoMagpie").

## The shared skills folder

- `~/.agents/skills/` is read by Codex, Cursor, Gemini CLI (as an alias), VS Code, Copilot CLI and Zed. Claude Code reads only `~/.claude/skills/`. Cursor and VS Code also read `~/.claude/skills/`, so a skill in both folders can appear twice there.
- `npx skills add` installs a symlink per agent to one canonical copy by default, or copies with `--copy` ([skills CLI](https://github.com/vercel-labs/skills)). Its installer puts the canonical copy in `.agents/skills/<name>`, skips the link for agents that read that folder anyway, and links the others' folders to it: a relative symlink on macOS and Linux, a directory junction on Windows; when the link fails, it copies ([`src/installer.ts`](https://github.com/vercel-labs/skills/blob/417405ecc8a03136f1675bcb19d5c05b299123f4/src/installer.ts), commit of 2026-10-07). `repomagpie setup` lays the skill out the same way ([decision 0035](decisions/0035-setup-and-doctor.md), "The skill"). Its global lock file is `~/.agents/.skill-lock.json` (version 3; each entry has its source and a folder hash, which `npx skills update` compares with GitHub) ([lock files](https://www.mintlify.com/vercel-labs/skills/advanced/lock-files), a mirror of the project's docs).

## Hooks: what an adapter could do

"Ask" is what our Claude Code hook does on an avoid note ([decision 0024](decisions/0024-recall-asks-on-avoid-notes.md)); "context on allow" is how the other notes reach the agent. Where an agent can't ask, or not reliably, the adapter denies the first try and lets the same command through on the next ([decision 0036](decisions/0036-hooks-in-other-agents.md)). Rows for the five agents of that decision checked 2026-10-15 (sections above); the shells marked "pre-check" are confirmed on a real machine before the adapters are built.
